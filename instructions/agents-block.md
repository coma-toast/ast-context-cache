## ast-context-cache

Prefer the `ast-context-cache` MCP tools over Read/Grep for exploring code: `get_context_capsule` (`mode="auto"`), `search_semantic`, `retrieve`, `get_file_context` (default `skeleton`), `get_project_map`, and `get_impact_graph` before changing an exported symbol. Use `search_docs` / `fetch_doc` for library docs instead of web fetches.

- **Session id:** pick one stable `session_id` per conversation and pass it on every ast-context-cache call, so repeated symbols are deduplicated and notes stay scoped to the thread.
- **Virtual context:** before host compaction (or about 70% context), `store_context` bulky plans or analysis and keep only the `[ctx_…]` stub; afterwards recover with `fetch_context`, `list_context`, or `search_context`. Treat every stored note as a mutable file you own: keep it current or shrink it with `edit_context` (in-place `append`/`replace`/`delete`/`rewrite`, undo with `revert`) rather than flushing and re-storing it, and never compact as a way to make room — each edit reports `tokens_reclaimed`, so shrink deliberately and check that number. Pass `expect_revision` when a note is shared across a handoff tree. If the same edit recurs every turn, register it once with `define_context_fn` and re-invoke it with `apply_context_fn` (off by default). Put prefs and short rules in `store_memory` / `recall_memory`.
- **Handoffs:** if your prompt contains `[handoff hof_…]`, call `open_handoff` first, before any search, and use the child `session_id` it returns. To delegate, `handoff` `create` and put the returned stub in the subagent prompt (`mode=fork` only for a host fork that inherited your window); a child ends with `handoff` `complete` and outputs the return stub `[result ctx_… for hof_…]`. Parallel subagents share one stub and coordinate through `scratchpad` (claims are advisory). After compaction, `handoff` `list` with your `session_id` recovers lost refs. Never put credentials in a brief.
