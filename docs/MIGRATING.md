# Migrating

Upgrade notes for releases that change behavior. Releases from 4.0.8 on update in place from the dashboard (Settings → Updates); see [INSTALL.md](INSTALL.md#updating).

## Migrating to 5.0

5.0 is the token-savings release: code tools answer in compact text, weak searches say so instead of padding the answer, and big results offload themselves. Each behavior change sits behind a feature flag that defaults on; turn one off in Settings → Features, or lock it with its `AST_FEATURE_*` variable (an env value wins over the dashboard), to get the 4.x behavior back.

| Change | What to do |
|--------|------------|
| **Text output by default.** `get_context_capsule`, `search_semantic`, `get_file_context` and `retrieve` return a summary line, then a `### file:start-end kind name (mode)` heading and fenced block per symbol. `output=locations` gives one `file:start-end kind name score` line per hit. | Scripts and code-mode callers that parse the JSON body pass `output=json`. `code_script_hints` are in the JSON body only; in text they move to `_meta.hints`. Flag: `feature_text_format` (`AST_FEATURE_TEXT_FORMAT=false` makes JSON the default again). |
| **`auto` semantics.** `auto` is full source for the top 3 delivered hits and skeletons for the rest; it never returns summaries. `get_file_context` with `auto` is `skeleton`. Dedup is mode-aware: a symbol already sent as a skeleton is sent again when you ask for it in full. | Nothing for most callers. Ask for `mode=full` when you need source for every hit. Flag: `feature_mode_v2` (off restores the score-ratio `auto`). |
| **`mode=edit`.** On `get_context_capsule` it returns the top hit's exact source plus skeletons of the functions it calls, and withholds the other hits. On `get_file_context` it needs `symbol` (a name or fqn) and returns that symbol the same way. `retrieve` rejects it. | Use it right before editing a symbol. With `feature_mode_v2` off, `edit` falls back to full source for the top hit (or `symbol`) and skeletons for the rest. |
| **Frozen tool lists for legacy sessions.** A session that started with `initialize` keeps the tool list it first saw until it reconnects, so a flag flip no longer invalidates its prompt cache. Modern subscribers get one coalesced `notifications/tools/list_changed` per burst of flag changes (sent 400 ms after the first, at most once per 5 s). | Reconnect (or start a new session) to see tools a flag change added or removed. A tool turned off after the freeze still returns its deny message when called. Changing a flag that affects tools asks for confirmation in the dashboard. |
| **Stats and timings moved to `_meta`.** Run-to-run variable fields (capsule `pipeline`, `cache_hit`, `input_tokens`, `output_tokens`; semantic `total_vectors`, `cache_hit`; retrieve's candidate counts and `search_time_ms` / `code_retrieve_ms` / `docs_retrieve_ms` / `dedup_budget_ms`) are in the result's `_meta["ast-context-cache/stats"]`, so identical calls return identical bytes. | Read them from `_meta`, or pass `debug=true` to keep them in the body (retrieve's timings come back as `timings`). Flag: `feature_stable_responses`. |
| **`export_bundle` and `import_bundle` removed.** | Re-index the project instead (`index_files`). Remove the names from `tools.json` if you listed them. |
| **Relevance floor.** Hits scoring below `min_relative_score` of the top hit are withheld and counted in `withheld` (`{count, tokens}`). A query whose top hit is weak returns no results and `no_match` (`{best_score, hint}`). Test, mock, vendored, generated and duplicate hits fold into `collapsed` unless the query is about tests. | Pass `min_relative_score` to loosen or tighten the cut for one call, and `collapse=false` to keep every hit. Defaults are settings: `relevance_min_relative` (0.7), `relevance_vector_min` (0.45 for the local ONNX model, 0.30 for other embedding backends) and `relevance_coverage_min` (0.5), with env overrides `AST_RELEVANCE_*`; see [USAGE.md](USAGE.md#relevance-floor). Flag: `feature_relevance_floor`. |
| **Self-offloading results.** A code tool result over `result_offload_threshold` tokens (default 2000) is stored as a `ctx_*` note and returned as its top hits plus a `[ctx_… <tool> <target>, <N> tok — head shown, fetch_context for all]` stub (in JSON, the `offloaded` field). Offloads expire after `offload_ttl_hours` (24) without a fetch; `fetch_context` on an expired ref returns `status: "expired"` with the `tool` and `args` that produced it. | `fetch_context(refs=["ctx_…"])` gets the whole result. Pass `offload=false` for the full result inline. Copy anything worth keeping into your own `store_context` note. Flag: `feature_result_offload`. See [USAGE.md](USAGE.md#host-context-clearing). |
| **Ledgers.** Tokens saved is now compression + dedup: compression is the full source of every returned symbol minus the tokens returned, and dedup is tokens not re-sent to a session. The query log and dashboard count the text actually returned (after rendering and offload), not the JSON body. A **conservative** figure uses each symbol ± 20 lines, merged per file, as the baseline. Virtual context and memory are a separate **virtual** ledger (tokens stored, fetched and recalled) and are not counted as savings. Rows logged before 5.0 counted tokens as bytes/4 and are reported as estimated. | Nothing. Expect lower but more honest totals than 4.x, and read the conservative line for a floor. Dashboards and scrapers: `astcache_ledger_tokens_saved_today{ledger="compression\|dedup"}` is new; `astcache_tokens_saved_today` keeps its name. |
| **Host usage (opt-in).** The `transcript_usage_ingest` setting (off by default; Settings → Storage) reads only the token usage fields of Claude Code transcripts hourly for an Overview chart. | Turn it on if you want host-side usage next to savings. |

## Migrating to 4.0

4.0 adds subagent handoff, live feature flags, and a safe installer, and tightens defaults. Rebuild (`make build`), restart, then re-run the installer.

| Change | What to do |
|--------|------------|
| **Localhost bind.** MCP and dashboard listen on `127.0.0.1` (plus `[::1]`) instead of every interface. | Nothing for local use. For LAN or container access start with `--listen 0.0.0.0` or `AST_LISTEN=0.0.0.0` (Docker images already set it). Anything that reached the server by LAN IP must be pointed at the new address. |
| **Origin / Host guard.** `/mcp`, dashboard writes, and the WebSocket return **403** for a non-loopback browser `Origin` (`forbidden origin`) or `Host` (`forbidden host`). | Native MCP clients send no `Origin` and are unaffected. Open browser tools from `localhost`; for a deliberate non-loopback setup, listen on the address clients use. |
| **Structured logs.** All logging moved to `log/slog` with `key=value` fields. | Update log scrapers. `AST_LOG_FORMAT=json` gives JSON lines; `AST_LOG_LEVEL=debug\|info\|warn\|error` (default `info`). |
| **Error strings.** Errors use the `errs` package: lowercase messages with structured fields, and handoff tools return `{"error": <code>, "message", "details", "suggestions"}`. | Match on stable codes (`error` field) rather than message text. |
| **MCP protocol.** The server is dual-era: stateless `2026-07-28` (per-request `_meta`, `subscriptions/listen`) plus legacy `initialize` for `2025-11-25`, `2025-06-18`, `2025-03-26`, and `2024-11-05`. It declares `listChanged` and sends `notifications/tools/list_changed`. | Nothing; clients negotiate. Clients that honor `list_changed` refresh their tool list when a flag changes. |
| **Three new core tools**: `handoff`, `open_handoff`, `scratchpad`, gated by flags `feature_handoff`, `feature_handoff_scratchpad`, `feature_handoff_claims`, `feature_handoff_live_trail` (all on), `feature_handoff_hooks` (off). | They appear in `tools/list` at every tier. To hide them, turn the flag off in Settings → Features or set `AST_FEATURE_HANDOFF=false` (an env value locks the flag), or disable them in `tools.json`. See [`docs/handoff.md`](handoff.md). |
| **Claude Code handoff hooks (opt-in).** `SessionStart`, `SubagentStart`, `SubagentStop`, and `PreToolUse` (`Agent`) hooks automate handoffs for Claude Code subagents. | Optional. Turn on `feature_handoff_hooks`, then `ast-mcp install --target claude_code --component hooks --yes` and restart Claude Code. They fail open. See [`docs/handoff.md`](handoff.md#claude-code-hooks). |
| **Query cache with `session_id`.** The search cache is now shared across sessions and used for `session_id` calls too (`feature_shared_query_cache`); entries are invalidated when covered files are reindexed. Dedup is immediate: a symbol returned to a session is deduped on its very next call (previously up to ~3s later). | Nothing. Results per session are unchanged; cache-hit statistics and latency improve. Set `AST_FEATURE_SHARED_QUERY_CACHE=false` to opt out. |
| **Scope fixes.** `search_context`'s keyword fallback now honors `session_id` / `project_path`, and memory vector recall no longer returns superseded, forgotten, or out-of-scope entries. | Nothing; results that leaked across scopes disappear. |
| **`retrieve` stats.** `stats.deduped_count` is now `stats.deduped`. | Rename the field in scripts that read it. |
| **Installer API.** `/api/agent-*` and project-scope installs are gone. | Use `ast-mcp install\|uninstall\|verify\|backups\|restore` ([`docs/INSTALL.md`](INSTALL.md#connect-your-agents)) or `/api/dashboard/installer*` (Settings → Agent integration). |
| **Pre-4.0 installs.** The old installer overwrote whole files; its Claude Code target could write markdown over `~/.claude.json`. | Re-run `ast-mcp install --target <host> --yes` (or `--target all`). The first 4.0 start re-checks old install records; the warnings print once on install and stay in `verify` and the dashboard until dismissed there. If Claude Code lost its config, restore `~/.claude.json` from `~/.claude/backups/` first. |
| **Claude Desktop** needs a stdio bridge: the installer writes `mcp-local bridge <url>`, or `npx -y mcp-remote <url>` when mcp-local is not on `PATH`. | Install the [mcp-local](https://github.com/coma-toast/mcp-local) release that adds the `bridge` command (the companion of this release), or have Node.js for `npx`, then quit Claude Desktop (it rewrites its config while running and drops the entry) and re-run `ast-mcp install --target claude_desktop --yes`. |
| **No `env` on URL entries.** Docs no longer suggest `env` blocks on `url` server entries; they never had an effect. | Remove them from your host configs if present, and set `AST_MCP_TIER` on the `ast-mcp` process instead. |

## Migrating to 3.0

| Change | What to do |
|--------|------------|
| Removed MCP ghost tools | `sync_remote` / `reset_*` gone from MCP; use local index + dashboard APIs |
| React-only dashboard | SPA at `http://localhost:7830/dashboard/` — not HTMX/templ |
| Keep-alive | `ast-mcp supervise` or Docker Compose `restart: unless-stopped` |
| Prometheus | Scrape `http://localhost:7830/metrics` |
| Overview confidence | Heuristics, weekly digest, session virtual-context stories |

Rebuild after upgrading (`make build` / `ast-mcp build`).
